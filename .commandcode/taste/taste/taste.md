# Taste
- Prefers large tasks broken into sequential phases matching natural sections of the project, tackled one phase at a time ("1 by 1"). Confidence: 0.8
- Wants a detailed plan written to a markdown file (e.g., `docs/PLAN.md`) as an executable, phase-by-phase checklist before implementation begins. Confidence: 0.75
- Keeps a standalone notes file as the source of truth for his requirements/vision and expects the plan doc to be re-read against it and continuously updated/persisted ("continuously update plan.md ... so that it is saved") as that source changes; before making edits he expects the agent to (re)read both the notes file and the plan and change code accordingly. Confidence: 0.75
- Prefers to supply/manage media assets himself (images and videos, e.g., "that i will provide later") and have the agent wire them into the site's references and use an interim placeholder until the real file lands, rather than generating final assets; he drops the real file into the project folder himself and expects the agent to locate it there by name and swap it in (e.g., names the exact files to use, like `slide_1…slide_5` in the video folder). Confidence: 0.75
- Favors a lean, uncluttered UI: repeatedly asks to strip decorative stat chips, helper/hint labels, redundant CTA links ("320+ clips delivered", "40+ brands", "See all projects"), filter/category buttons ("remove the buttons like short form, medical & aesthetic"), whole form boxes he doesn't need ("remove the 'what do you need box' and 'budget' box"), and leftover footer content. Confidence: 0.65
- Communicates in terse imperatives and expects the agent to just execute the instruction ("do as i said", "make the changes as said") rather than pause for clarification or confirmation (e.g., "read the ... file and make changes ... according to information i gave you"). Confidence: 0.7
- When adapting a downloaded template/site, prefers to keep the existing design and CSS untouched and change only content/copy, personal details, links, and images. Confidence: 0.8
- Prefers placeholder tokens (e.g., `{{NAME}}`, `{{EMAIL}}`) left in the files to be filled in later, rather than hard-coding personal details up front. Confidence: 0.6
- When rebranding a template, wants the previous owner's identity purged everywhere, not just in visible copy: replace every text with his agency's information (brand name, email in markup AND in JS constants/config, location — "keep in mind the agency is based in dhaka") and remove leftover template artifacts like the old footer/brand block. Confidence: 0.6
- Cares about polished, balanced layout spacing: flags large empty gaps between sections as "looking so bad" and asks for them minimized/tightened so the page reads as intentional. Confidence: 0.6
- Defers aesthetic judgment to the agent — states the goal ("so that it looks good") and expects it to choose concrete sizes/spacing values itself rather than being asked for exact numbers. Confidence: 0.55
- Drops change requests as a plaintext instruction file inside the project (e.g., `demos/replace.txt`) and expects the agent to open that file and implement exactly what it says. Confidence: 0.6
- Wants work saved/checkpointed so he can "start from where I left" — values a persisted resumable state (status + "resume here" notes, and a version-control checkpoint) before pausing a session, so a later "continue the plan" picks up seamlessly. Confidence: 0.55
- Likes rich, interactive, motion-driven presentation: asks for smooth sliding/scroll effects, cards arranged on a curved/arc ("half circular") path, click-to-enlarge media at Instagram-reel size with sound, playful/expressive "super funky" hero typography, etc. — prefers immersive layouts over static grids. Confidence: 0.55
- Motion/animation is a per-element want, not a hard rule: he pushes for bold expressive type first ("make the text funky") and will strip the motion back while keeping the look (asked for the hero headline floating, then said "no need to float the text" and kept it white and funky/static), so animation should be treated as optional polish he may drop. Confidence: 0.5
- Prefers explicit, user-controlled interactions over automatic ones: for carousels/sliders he wants press-and-hold-then-drag to move the cards (the row only moves while the pointer is down), NOT automatic cursor-follow/mouse-position-driven sliding — because cursor-follow steals clicks. Confidence: 0.7
- Wants hero/ambient video to autoplay on its own with sound while the section is in view, and prefers custom minimal controls over the browser's native player chrome — explicitly "no button but only one button, that the mute button" (no `controls`, single mute/unmute toggle). Confidence: 0.6
- Hosts/deploys static sites via GitHub + Netlify, connecting the repo in Netlify and deploying from the default branch; when asking for deployment help he wants just the concrete steps and exact field values to use ("just drop me steps"). Confidence: 0.6
- Prefers visual consistency with the rest of the design over one-off treatments for a single element: when he drops an expressive flourish he wants the element brought in line with the established style elsewhere on the site (e.g., after asking for an ultra-funky hero title, he reverted it to plain text, "keep it simple as in the header") rather than keeping a unique look. Confidence: 0.55
- Dislikes the generic "AI slop" look — dark glassmorphism, violet/fuchsia gradients, coloured glow blobs, grain/noise overlays — but his aesthetic calls are reversible and not deeply held: after asking for a clean light/white "editorial" theme with a black grid, he reversed himself ("i have made a mistake ... i like the purple theme that was before") and had the original dark-violet glass theme restored, so restyling decisions here should be treated as provisional. Confidence: 0.55
